# 公共硬约束（所有任务必须遵守）

> 本文件是所有任务的共享约束，任务一、二、三的 sub-agent 在启动时**必须先读取此文件**，再读取具体任务规范。

---

## 硬约束

### 1. 文件写入

#### 写入前必须先列计划（强制）

在动手写任何笔记或综述之前，**必须先在对话中输出写入计划**，格式如下：

```
📋 写入计划：
- 预估总字数：约 X 字
- 分段数：Y 段
- 第1段（PART1）：frontmatter + 引言 + 背景，约 Z 字
- 第2段（PART2）：核心章节A + 核心章节B，约 Z 字
- ...
- 最后一段：结尾 + 总结，约 Z 字
```

确认计划合理后再开始写入，不得跳过此步骤。

#### 分段写入规则

**每段严格不超过 5,000 字**（含空格、标点、代码），超出 `Write` 工具会报 `content is missing` 错误。宁可多分段，不可超限。

**分段写入策略（Write + Edit，禁止使用 python3）**：

1. **第一段**：用 `Write` 工具创建文件，内容末尾必须加锚点标记：
   ```
   <!-- CONTINUE -->
   ```

2. **后续每段**：用 `Edit` 工具，将上一段末尾的锚点替换为"新内容 + 新锚点"：
   ```
   old_string: <!-- CONTINUE -->
   new_string: （新内容）
   <!-- CONTINUE -->
   ```

3. **最后一段**：用 `Edit` 工具，将最后的锚点替换为最终内容（不再加锚点），文件写完。

**示例（3段写入）**：
- Write：`# 标题\n\n第一段内容...\n<!-- CONTINUE -->`
- Edit1：`<!-- CONTINUE -->` → `\n\n第二段内容...\n<!-- CONTINUE -->`
- Edit2：`<!-- CONTINUE -->` → `\n\n第三段内容（结尾）`

#### 禁止事项

- **禁止：`Bash` + `cat << 'EOF'`**——Markdown 中的反引号等特殊字符会导致 shell 解析错误
- **禁止：`Bash` + 参数拼接内容**——系统有 MAX_ARG_STRLEN 的 128KB 硬限制
- **禁止：Write 工具写入超过 5,000 字的内容**——必须分段

### 2. 进度汇报

执行耗时任务时，每完成一个步骤或每隔 1-2 分钟必须向用户输出进度（做了什么、下一步是什么、是否遇到问题）。不要长时间沉默。

### 3. 工具调用失败处理

重试 3 次以内仍失败，必须立刻向用户报告，不要自己反复尝试浪费时间。

## Red Lines（内容质量红线）

### 1. 禁止编造参考文献

相关工作中引用的每篇论文，必须来自以下来源之一：
- 原论文的参考文献列表（通过 WebFetch 从论文 HTML/PDF 读取到的）
- WebSearch 实际检索并返回的结果中明确存在的论文

宁可少写，也不编造。

### 2. 禁止编造代码/项目地址

Code 链接必须来自论文原文中作者明确提供的地址，不得根据作者名、组织名、项目名自行拼接 GitHub URL（即使看起来合理）。若论文未提供代码链接，写"暂未开源"或省略该字段。

### 3. 数据与结论须有原文依据

实验数字（如"提升 X 倍"、"降低 Y%"）必须能在原文找到对应表格或句子。推断或估算的数据须加注"（推断）"或"（约）"。

---

## 图片路径规范

- 存放：content/assets/主题名/（统一位置，不放在 md 同级目录）
- 引用格式：以 /assets/ 开头的绝对路径，例如 /assets/主题名/image.png
- 不得用相对路径（Quartz 会错误地将相对路径转换为相对 URL）
