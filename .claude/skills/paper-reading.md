# 论文深度阅读工作流（迭代检索 + 冲突-消解式递进拆解）

**核心理念**：先拼凑完整知识全图，再落笔写笔记。每一轮检索都有明确目标，每轮结束后公开下一步计划。技术拆解遵循**四层栈**（算法 → 数学 → 硬件实现 → 多模型泛化），每层以"发现冲突 → 消解冲突"的叙事结构推进。

---

## 阶段一：定位目标文献 + 制定多阶段分析规划

**目标**：锁定元数据，同时在对话中宣告本次研究的完整分析规划。

1. 用论文 arXiv ID 或标题执行学术搜索（`WebSearch`）
2. 提取并公开报告：
   - 论文完整标题、作者团队与所属机构
   - 发表会议/期刊与年份、arXiv/DOI 链接
3. **宣告多阶段分析规划**：明确列出后续将深入的 4-5 个技术维度，让读者知道全貌
   > 示例："我制定了多阶段分析规划：①研究背景与冲突点 ②核心算法与数学推导 ③近似机制的置信度校验 ④GPU 算子实现与分布式部署 ⑤多模型实测评估"

---

## 阶段二：洞察研究背景与核心制约关系

**目标**：理清"为什么做"，即现有方案中相互制约的矛盾对。

用 `WebFetch` 抓取论文摘要页（`arxiv.org/abs/<ID>`），重点提取：

- **制约对**：论文解决的是哪两个目标之间的张力（如"KV 缓存命中率 vs 负载均衡"、"稀疏计算 vs 精度保持"）
- **现有方案的核心瓶颈**（量化描述，如"X% 吞吐浪费"、"需繁琐超参调优"）
- **论文的核心主张**：一句话说清提出了什么、如何消解这对矛盾

完成后输出：**下一步计划**——将攻坚以下几个技术维度

---

## 阶段三：四层技术栈递进拆解

每层独立一轮，每轮遵循固定叙事结构：
1. **点出该层的认知冲突**："我发现了 X 与 Y 之间的矛盾……"
2. **搜索/分析，消解冲突**："通过深入分析，我发现论文通过 Z 机制解决了这一问题……"
3. **宣布下一层计划**

### 层 1：顶层算法决策与核心方法论
- 核心公式/架构的精确表达（变量名、符号要具体，不能只说"乘法"或"散度"）
- 关键指标/组件的选择依据（为何选 X 而非更直觉化的 Y）
- 系统如何在制约对之间取得平衡（即消解阶段二中的矛盾对）

### 层 2：数学推导与理论支撑
- 核心公式的推导过程（超参如何消去、阈值如何自适应）
- 理论支撑：论文借助什么数学框架（Lyapunov、排队论、信息论等）
- **置信度校验机制**：若方法使用近似/粗估，论文如何验证近似结果与真实分布的契合度
  > 典型模式：用代表性子集计算精确值，以散度/距离度量作为置信度开关；不达标则回退至鲁棒的几何/静态基线

### 层 3：底层实现与工程落地
- **算子实现**：使用什么框架（Triton、CUDA、Rust）、如何处理动态/非连续索引
  > 典型挑战：稀疏索引不规则 → 需要块级重排 + 对齐才能映射为硬件友好的密集矩阵乘
- **分布式部署**：多卡并行（TP/PP/EP）时动态负载是否会导致"木桶效应"？论文如何解决
- 是否开源，仓库地址（**必须来自原文，不得推断或拼接**）；规模化部署经验

### 层 4：多模型泛化验证与量化实验
- **跨模型验证**：在 3 个以上不同模型家族（如 LLaMA / Qwen / GLM）上的表现是否一致
- 对比基线系统（列全，包括工业级生产系统）；核心指标具体数值
- 覆盖的工作负载类型（Chatbot / API / Coding Agent 等）
- 消融实验：哪个组件贡献最大；精度 vs 速度的 Pareto 曲线

---

## 阶段四：宣告"停止检索，进入合成"

当四层栈全部覆盖后，**明确宣告**：
> "我已完成对该论文从顶层算法决策、数学推导、底层算子实现到多模型实测的全方位复盘。现在停止检索，进入知识全图确认与笔记写作阶段。"

然后输出**知识全图确认清单**：

```
✅ 元数据：标题 / 作者 / 机构 / 会议 / 年份 / 链接
✅ 核心制约对：[X vs Y，已理清]
✅ 层1 算法：[核心公式 + 指标选择依据]
✅ 层2 数学：[推导过程 + 置信度校验机制]
✅ 层3 工程：[算子实现 + 分布式部署 + 开源链接]
✅ 层4 实验：[跨模型数据 + 基线对比 + 消融]
⬜ 相关工作：[待补充 / 已从参考文献列表提取 N 篇]
```

如有空缺，先补全再写笔记。

---

## 阶段五：相关工作检索

目标 20-30 篇，硬下限 10 篇，**全部必须来自实际检索结果**。

- 来源一：`WebFetch` 抓取论文 HTML 全文中的参考文献列表
- 来源二：`WebSearch` 多轮检索（先驱/对比基线/近期 Follow-up/Survey）
- 按类别整理：先驱工作 | 直接对比方法 | 近期 Follow-up

---

## 关键纪律（Red Lines）

| 规则 | 说明 |
|------|------|
| 阶段一必须宣告完整分析规划 | 让读者在开始前知道全貌 |
| 每层以"冲突-消解"结构推进 | 不只是罗列方法，要揭示矛盾与解决逻辑 |
| 置信度校验是必答题 | 凡近似方法必须追问：论文如何验证近似不失真 |
| 层3工程实现为必选 | 硬件落地是系统论文的核心，不得跳过 |
| 四层栈全覆盖后才宣告停止检索 | 明确宣告是防止无限检索的终止条件 |
| 知识全图确认清单全绿才落笔 | 先拼图后写笔记 |
| 禁止编造任何论文/数据/链接 | 所有引用必须来自实际检索结果 |
| 数据必须有原文依据 | 推断数据加注"（推断）"或"（约）" |
